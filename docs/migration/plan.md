# 既存資産の移行計画

状態: 設計案。データ移行は未実施。

## 移行するもの

| 移行元 | Compassでの扱い |
|---|---|
| library/sources | 原資料の不変な版。元名・元パス・SRC-ID・SHA-256を保持 |
| library/catalog | 文書メタデータ、プロジェクト関連、移行ID対応 |
| library/principles | 本人の個人方針。初期閲覧者は本人のみ |
| library/knowledge | 共通知識候補。資料ごとに共有範囲を決める |
| library/projects | プロジェクト、知識、方針、判断、タスク候補 |
| Project_KnowledgeのファイルとSQLite | 原本、履歴、出典、社員・グループ、権限、除外 |
| .pkbudget | 元文書版を保管し、予算版・月次予算・実績へ変換 |

旧アプリのファイルだけをコピーして完了としません。SQLite内の原本履歴・ID・出典・共有権限も必要です。
セッション、APIキー、接続先の秘密値を事業文書として移行せず、新環境で設定・再ログインします。
参照元の一覧は[参照元](../reference/sources.md)にあります。

## 守る条件

- 原資料の本文・バイト列を変えない。識別情報は対応表・manifest側に保持する。
- IDはパス名や連番だけで同一視せず、移行元の名前空間と元IDを記録する。
- 同じ内容でも履歴・出典・権限が違う文書を自動的に統合しない。
- 初期案・過去の予定・未確認タスクを現在の確定事項へ変換しない。
- 個人資料、特定社員への文書共有、プロジェクトからの明示除外を維持する。
- 文書の整理段階「公開用」を匿名公開や全社公開へ置き換えない。
- 施策への配賦額とプロジェクト予算、月次集計と取引明細を二重計上しない。
- 繰り返し実行しても同じ取込元から文書・予算が重複生成されないようにする。

## 既知の移行課題

図書館の初回原資料は60件・5,815,496 bytesです。
最大MDは4,163,819 bytesで、現行Project_Knowledgeの2MiBテキスト上限を超えます。
原本保存・抽出・索引・AI送信の上限を区別し、原本を切り捨てず保存する必要があります。

不足画像3件と、一部本文の文字化けは旧図書館の取込記録に記載されています。
この状態を引き継いで利用者へ示し、存在しない画像や補正済みの本文を作ったことにしません。
資料台帳の「279件」は台帳内の件数であり、原資料ファイル数とは異なります。

## 試行から切替まで

1. **棚卸し**: 移行対象、元ID・パス・ハッシュ、版、権限、現在の更新場所を記録する。
2. **コピーによる試行**: 新環境でプレビューし、件数、原本、リンク、履歴、予算合計、権限を照合する。
3. **業務確認**: 2人以上で依頼・結果提出・確認、文書限定共有、AI参照範囲を確認する。
4. **切替準備**: 対象の旧環境の書込みを止め、最終差分を取込む。バックアップの復元を確認する。
5. **更新先の切替**: 対象データの唯一の更新先をCompassにする。
6. **安定確認**: 旧環境を参照用に保管し、新側での更新・不具合を追跡する。

一括移行の前に、P001など範囲を限定した試行を行います。
ただし複数プロジェクト共通の文書は文書IDごとに一つの更新先を持ちます。
共通文書を切り替えたら、未移行プロジェクトからも旧文書を更新しません。

## 正本の切替

| 対象 | 切替前 | 切替後 |
|---|---|---|
| 図書館のタスク | 既存MD | Compassの共有DB |
| 原資料 | 既存フォルダ・原本履歴 | Compassが保管する不変の原本版 |
| 知識・方針 | 既存MD・文書 | Compassが管理する文書版 |
| 共有・権限・予算 | 既存Project_Knowledge | CompassのDBと文書版 |
| ローカル出力 | 元の編集資料 | ID・版を持つ編集用コピー |

今回Compass/docsに設計を集約したことと、事業データの正本切替は別の作業です。
現時点では旧資料・旧アプリをそのまま利用します。

## 戻す場合

切替後にCompassで追加された仕事・結果・文書を先に保全します。
元バックアップへ単純に戻して新規データを失う方式にせず、差分を旧側へ反映できる範囲を確認します。
復旧後も文書ID、予算、権限、出典の対応を照合します。

## 完了判定

[受入条件](../requirements/acceptance.md)の原本・予算・権限・競合・復元に関する項目を満たすこと。
自動取込件数が一致するだけでは完了にしません。
