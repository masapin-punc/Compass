# 運用手順と本番準備

## 現在利用できる環境

現在はローカル開発とdocs閲覧の環境です。
Django runserverとMkDocs serveは127.0.0.1に限定して使います。
起動・停止・設定手順は[開発環境](../development/setup.md)を参照してください。

環境変数の見本はCompass直下の.env.exampleです。
自動で.envを読み込む実装はなく、PyCharmまたはOSの環境変数で設定します。
DEBUG=False用のキー検査だけで、本番運用の準備が完了するわけではありません。

## 本番構成の案

- 共通URLで利用するWebアプリ。
- 重い取込・抽出・索引・AI処理を行うworker。
- PostgreSQLによる共有データ管理。
- 非公開の原本・添付保存領域。
- 監視・バックアップ・復元手順。

既存Ubuntu環境は試行候補です。本番の運用負荷を減らすなら管理サービスも比較します。
配置先、費用、担当者、資料の保管条件は[未決事項](../planning/open-questions.md)で管理します。
デプロイ設定やサービスを本番へ適用する段階にはまだ進んでいません。

## 運用開始前に具体化すること

| 対象 | 必要な運用 |
|---|---|
| アカウント | 社員認証、参加・退会、停止、権限理由の確認 |
| 共有範囲 | 原資料、予算、個人方針、AI生成物の閲覧制御 |
| サービス | 本番プロセス、HTTPS、秘密設定、ヘルス確認 |
| データ | DBと原本のバックアップ、保管期間、別環境復元 |
| ジョブ | 再試行、重複実行防止、失敗・停止の確認 |
| AI | 利用を許可した接続先・資料、送信範囲、費用上限 |
| 監視 | アプリエラー、空き容量、バックアップ・ジョブ失敗 |
| 更新 | 適用前確認、DB移行、復旧、更新履歴 |

既存の「共有資料の外部AI送信停止」は、利用条件が確定するまで引き継ぐ前提です。
Compassを準備しただけで既存方針を解除しません。

## バックアップ案

DB、原本、必要な設定の対応が復元できる単位で保全します。
書込み中のDBファイルを単にコピーして整合性を保証する運用にはしません。
索引は再構築できる設計とし、原本と権限を復元の基準にします。

日次バックアップ、RPO 24時間以内・RTO 4時間以内は要件定義時点の提案値です。
担当者・保存先・保持期間・復元試験の頻度を決め、本番条件に合わせて確定します。

## ドキュメントの配布

現時点ではdocsは開発者がローカルで読む用途です。
公開サーバへの配信、GitHub Pages等の公開設定は作成していません。
将来社内共有する場合は設計文書の閲覧対象とアクセス方法を定めます。
