# ADR-0002: 一つのWebアプリへ統合する方針案

- 状態: 提案
- 作成日: 2026-09-29
- 関連: [構造設計](../architecture/structure.md)、[未決事項](../planning/open-questions.md)

## 背景

現行Project_Knowledgeは利用者端末のローカルアプリから共有サーバへ接続します。
メンバー間の予算・施策・タスク・資料共有を増やすにあたり、配布・更新・同期の負担を減らしたいという要望があります。

## 提案

ブラウザから中央のWebアプリを使い、機能を一つのPythonアプリ内で分けます。
既存のCompassはDjangoで作成済みのため、その初期構成を開発基盤として活用します。
共同利用のDBはPostgreSQLを推奨し、原本保存は非公開の別領域を使います。

## 現在確定している実装

- Compass/compassにDjangoの設定・起動構成がある。
- 現在のDB設定は開発用SQLite。
- 業務モジュール、PostgreSQL、認証・AI連携は未実装。

## 判断が残る条件

オフラインが必須なら、ローカルクライアントの併用を再評価します。
社外共有、利用規模、本番配置先、AI利用先は別途確認します。

## 比較した案

- 現行方式を継続: ローカル利用に強いが、利用端末ごとの更新・接続が残る。
- Web中心: チームの現在値と更新先を一つにしやすい。
- 自動双方向同期: オフラインには有利だが、競合・権限変更・同期の管理が増える。

## 検証条件

ブラウザ認証、文書単位権限、既存予算、4MB超MD、原本・履歴を最初の小さな試行で確認します。
採用判断の更新時は、変更理由と条件をこの記録に追記します。
